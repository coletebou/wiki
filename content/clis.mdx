A command-line tool is the cheapest way to give an agent a new capability. It documents itself (`--help`), it can
print JSON for the next tool in the pipe, it reports success or failure with an exit code, and it costs nothing at
all until it runs, unlike an MCP server whose tools are listed in every session. Models have read an enormous amount
of shell, so they are good at it. Most of Cole's setup is CLIs, and the agents drive them all day, the same way a
person would.

## Why agents like CLIs

- **Self-documenting.** An agent that meets an unfamiliar tool runs `tool --help` and carries on.
- **Composable.** `gh api … | jq …` answers questions no single tool was built for.
- **Testable.** A CLI has inputs, outputs and an exit code, so it gets real tests (see [[testing]]).
- **Shared with the human.** The command an agent ran is one Cole can run, read in a transcript, or put in a script.
- **Cheap in context.** Nothing loads until a command is used, and output can be filtered before it reaches the model.

The tradeoff is structure and authority. A long-lived connection, credentials the agent should not hold, or results
gathered across machines fit better behind an [[mcp|MCP server]]. Cole's [[drover|Drover]] offers both: every
capability is one op, available as `drover op <op>`, as an MCP tool and as a button.

| `gitleaks` | Secret scanning on every commit and push |
| `claude`, `codex` | Starting more agents, headless (`claude -p`, `codex exec`) or in tmux |

Inside [[Claude Code]] there is one twist: Cole's rules tell agents to prefer Claude Code's built-in Read, Grep and Glob
tools over `cat`, `rg` and `find` within a session. The shell versions are for pipelines, scripts and machines without
the agent.

Tools arrive on each machine through the [[bootstrap-script]], [[homebrew|Homebrew's Brewfile]] on macOS and pinned
Node tool versions everywhere, so every machine has the same versions. Plugins can ship their own CLIs too: Claude
Code puts a plugin's `bin/` directory on the Bash tool's `PATH` while the plugin is enabled (see
[[skills-and-plugins]]).

## How Cole designs a CLI for agents

Patterns that recur across Cole's tools:

- **Results on stdout, conversation elsewhere.** `wt-helper` writes its prompts and status lines to the terminal and
  prints only the final path on standard output, so a shell function can capture it.
- **Exit codes that mean something.** `cc-handoff launch` documents eight: 0 started and replied, 2 bad arguments or an
  unready brief (nothing started), 3 a required tool is missing, 4 a successor already exists (never relaunch), 5 tmux
  failed (a window that opened is left running), 7 started but not replied yet, 8 no launcher reproduces the
  session's route, 9 the remote preflight failed. An agent can branch on the number instead of parsing prose.
- **A dry run for anything that changes things.** The installer's `--dry-run`, `cc-park list`, `pw validate`, and
  `--print` on the handoff launcher all show the plan and touch nothing.
- **Refuse rather than guess.** A brief with a placeholder left, an unknown launch flag, a volume that is not mounted:
  the tool stops and says why.
- **Never print a secret, never take one in argv.** Values come from standard input or a hidden prompt, because other
  users can read a process's arguments, and status commands print names, never values.
- **Gates fail closed, helpers fail open.** A secret scan that cannot run blocks the push; a helper hook that breaks
  just steps aside.
- **Idempotent.** Running it twice changes nothing the second time; the installer moves anything it replaces into a
  dated backup with a log.
- **Portable.** Most of Cole's scripts run on macOS's stock bash 3.2 as well as on Linux, so they avoid tools that
  differ between BSD and GNU (`sed -i`, `readlink -f`, `date -d`, `stat`). See [[posix]].

## Gotchas

- **Interactive prompts hang agents.** Anything that waits for a password, a passphrase or a browser callback stalls a
  headless session. Give automation `--batch`, `BatchMode=yes` for SSH, and tokens instead of logins.
- **Pipes hide exit codes.** Without `set -o pipefail`, `gate | tail` exits with `tail`'s status. Wrap a gate so the
  wrapper exits with the gate's own code.
- **Huge output is expensive.** Filter before printing: `rg` with a glob, `jq` with a selection, `tail -n 50`.
- **`pgrep -f` matches more than you think.** It also matches every other session's polling loop that mentions the
  same pattern; match by exact process name with `pgrep -x`.
